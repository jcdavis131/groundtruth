# MCP server

Embedding Atlas exposes its keyless JSON API as a [Model Context Protocol](https://modelcontextprotocol.io) server so an agent (Claude Desktop, Claude Code, any MCP client) can pull the same water, economy, series, indicator and filings data a notebook can, with the same provenance fields. The MCP layer holds no data logic: every tool builds one `/api/...` URL and relays the route's JSON verbatim. When a route is missing on the server you point at (an older deployment answers its HTML not-found page), the tool answers that 404 plus `note: "this route is not deployed on this server"` instead of failing. A route's own JSON 404 (an unknown ticker, a CIK that is not a company) is relayed with `note: "route answered HTTP 404"`.

## Transports

| Transport | Where | How |
| --- | --- | --- |
| Streamable HTTP, stateless | `POST https://<host>/api/mcp` | JSON-RPC 2.0 in, JSON out (`enableJsonResponse`); no session id, no SSE stream, no auth. `GET /api/mcp` returns a JSON description with the tool manifest; `OPTIONS` answers CORS. Bodies over 1 MB are refused (413), non-JSON content types with 415. |
| stdio | `node scripts/mcp-stdio.mjs` | For local clients. Calls the HTTP API at `GEV_BASE_URL` (default `http://localhost:3000`). Compiles `lib/mcp` with tsc into `.tmp-mcp/` on first run (see the script header for why not `--experimental-strip-types`). |

Client setup and curl examples: [examples/README.md](../examples/README.md).

## Tools

Arguments are validated with zod before any request is made; a bad argument comes back as an `isError` result naming the field, not as a fetch. Every result is the route's JSON as `structuredContent` and as text. Polygon collections (`areas`, `countries`) have their geometry set to null unless `geometry: true`, and any result over 48,000 characters has its feature list halved until it fits, with a `note` saying how many items were dropped. The limit sits under Claude Code's 50,000-character mark, past which it writes a result to a file and shows the model only a path (anthropics/claude-code CHANGELOG.md: "Tool results larger than 50K characters are now persisted to disk (previously 100K)").

`world_context` is the one tool that composes several routes into one bundle (personal-world-jev slice 1). It keeps the same rules per item rather than relaying a route verbatim: every item cites its source, a failing route costs only its own items (`coverageStatus` partial), and the reply is capped at 40,000 bytes. Each item also carries the publisher's own record-level URL where one exists (`upstreamRecordUrl`), so an agent can cite the publisher rather than eye. [JEV.md](JEV.md) says how an agent uses it.

### What a client sees before it searches for a tool

Claude Code 2.1.x does not load every tool's description at session start. It loads tool names and the server's `instructions`, and fetches a description when a tool search finds the tool. So this server sends, at `initialize`, the instructions below (`INSTRUCTIONS` in `lib/mcp/server.ts`, held to 1,500 characters by `server.test.ts`):

```text
eye is a read-only map of public, keyless US data about a place: a point, a county, a box or a record. Every answer names its publisher.

Search for these tools before acting on a place, before citing a place fact, and before saying something does not exist for a place.

Start with world_context: one call for a point, a county FIPS or a box returns identity, fabric, hazards, economy, vulnerability, institutions, water and freshness, each item with its publisher and record URL. Then place_fabric for the units a point sits inside, and catalog_search to find which collection could answer a question. The other tools go deeper on one topic.

Two rules:
1. Cite upstreamRecordUrl, the publisher's own URL for that record (upstreamUrl where the note says there is no record-level URL). Do not cite eye for a number a publisher owns.
2. Read missing[] before relying on an absence. An entry there says what could not be answered and why; it is not a zero. coverageStatus partial means something is missing or was cut.
```

`world_context` also declares `_meta: { "anthropic/alwaysLoad": true }` on its `tools/list` entry, which makes Claude Code load its description upfront; no other tool does, and a test pins that. It costs roughly 600 tokens in every session that uses this server, place-related or not. The same flag is in `GET /api/mcp` as `tools[].alwaysLoad`, next to `instructions`. The MCP SDK passes `_meta` through `registerTool` (checked in `@modelcontextprotocol/sdk` 1.30.0). Every description is held to 3,800 characters (Claude Code cuts upfront descriptions and server instructions at 4,096 characters; before v2.1.296 the cap was 2,048, per its CHANGELOG.md entry for 2.1.296, "Changed the default limit on MCP tool descriptions sent up front and on MCP server instructions from 2,048 to 4,096 characters"; `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`, added in 2.1.280, sets that cap, and the `_meta["anthropic/alwaysLoad"]` flag is named in the 2.1.285 entry). The instructions share the 4,096 cap and are 1,017 characters, so they are not cut, and `world_context`'s first 300 characters say to call it before acting on a place and to cite `upstreamRecordUrl`.

### Errors

Every `isError` result is a JSON object, as `structuredContent` and as text. `error` is the message string it has always been (the route's own when it sent one). Next to it:

- `code`: a stable id, one of `invalid_arguments`, `bad_request`, `not_found`, `route_not_deployed`, `rate_limited`, `upstream_failure`, `upstream_rejected`, `timeout`, `server_unreachable`, `internal_error`.
- `category`: `invalid_input`, `unavailable`, `timeout` or `execution_failure`.
- `retryable`: `true` only when the same call can succeed later unchanged (rate limits, an upstream that did not answer, timeouts, an unreachable server). A bad argument, an unknown id, a route this server does not have and a crash are `false`.
- `remediation`: one sentence on what to do next.

An error reply is held to 10,000 characters (`ERROR_MAX_CHARS` in `lib/mcp/tools.ts`). Past that, `boundErrorPayload` cuts the lists that repeat themselves to their first entries (each topic's `missing`, then each `coverageStatus.basis`), then clips long text, and says so in `note`; the five fields above are never dropped. A route's other fields (`note`, `details`, `upstream`, `status`) stay in the object. The schema is `ERROR_ENVELOPE_SCHEMA` in `lib/mcp/errors.ts`, and the codes with their category and retry answer are `ERROR_CODES` there. The shape follows morluto/rea's error contract (MIT), rewritten smaller.

### Coverage status and absence codes

Every place eye says something is missing, it says with a **code** and the **action** an agent may take. The codes are a closed list (`ABSENCE_CODES` in `lib/mcp/absence.ts`); the free-text `reason` stays beside them, so nothing that read it breaks.

| Code | Action | Retryable | FHIR data-absent-reason | What it asserts |
| --- | --- | --- | --- | --- |
| `not_published` | abstain | no | `unsupported` | The publisher does not publish this here, said by a route's own missing entry (today only Puerto Rico) or a publisher's suppression flag. Never eye's guess, and never a row value: FEMA's rating words ("Insufficient Data", "Data Unavailable") are `not_in_release`. |
| `not_in_release` | abstain | no | `unknown` | The source answered and its current release has no row or value for this place. |
| `withheld` | abstain | no | `masked` | The publisher suppressed the value with its own flag (BLS QCEW `jobs.suppressed`). The item is null, with `absence: "withheld"`, never 0. |
| `join_gap` | narrow | no | none | eye could not attach the source's rows to this place (a boundary or vintage mismatch such as Connecticut's legacy counties); the source may hold the value. |
| `filed_under_other_code` | redirect | no | none | The source files rows for this place under another place's code; they are not attached here. `to` names the other code when the route gives it (none does today). |
| `not_asked` | narrow | no | `not-asked` | This part was not requested or cannot be answered for this kind of place; ask with a county FIPS or a point. |
| `not_loaded` | narrow | no | none | Part of the place or source was not loaded on this call (a smaller box, a bundle that is not a full pull). |
| `cut_by_route_limit` | narrow | no | none | The route hit its own record limit, so the list is a floor. |
| `cut_by_max_records` | narrow | no | none | The list was cut to `max_records`; there are more. |
| `cut_by_byte_cap` | narrow | no | none | The reply was cut to its byte cap; ask for fewer topics or a smaller place. |
| `failed` | retry | yes | `error` | A route or its upstream failed on this call; nothing is known about the value. Agrees with `upstream_failure` and `rate_limited` in the error codes. |
| `timeout` | retry | yes | `temp-unknown` | A route or its upstream did not answer in time. Agrees with the `timeout` error code. |
| `no_citation` | none | no | none | The route sent no provenance for this source, so nothing from it is shown; this does not say the value is absent. |
| `about_eye` | none | no | `not-applicable` | A claim about eye's own catalogue has no upstream to cite. |

Actions: **abstain** says the value is absent here (a reader should say so, not search elsewhere in this tool); **retry** means the same call can succeed later; **narrow** means change the request (a county FIPS or a point, a smaller box, fewer topics, another `max_records`); **redirect** means the value is filed under another code; **none** asks nothing and claims no absence. `not_published` and `withheld` are never retryable and always abstain, and they are set only from a route's own missing entry (`ROUTE_REASON_CODE`) or a publisher's own suppression flag: when eye cannot tell, the code is `failed` or `not_asked`, because a code that lies is worse than prose. The FHIR column is the nearest value in HL7's data-absent-reason set (none where FHIR has no such notion).

A `world_context` missing entry is `{ what, code, reason, action, to? }`. A result carries `coverageStatus: { status: "partial", basis: [{ code, text }, ...] }` only when eye can say so from fields it already sends: a place export that lists places whose value is unknown (`data.nullPlaces`, `data.nullCells`; the code is the route's own reason code for them), a route that says its list was cut (`data.truncated: true`, `cut_by_route_limit`), a route that lists upstreams that failed (`data.failed[]` or `failed[]`, `failed`), a route whose `meta.bbox` is smaller than the box asked (`not_loaded`), or a list the MCP cut to fit (`cut_by_byte_cap`). There is no `"complete"`; a result without `coverageStatus` makes no coverage claim, and its caveats and provenance still say what it covers. It is not called `coverage` because some routes already send a `coverage` array of their own.

### Output schema

`world_context` publishes an `outputSchema` (JSON Schema, `lib/mcp/worldSchema.ts`, `schemaVersion` `"world/2"`): in `tools/list` and in the `tools` list of `GET /api/mcp`. `schemaVersion` is a new key on the reply and the change is additive within world/2; the server version that carries it is 0.4.0, and `kind` `"estimate"` with `inputs` came with 0.5.0 (see the versioning promise below). The schema encodes the honesty rules so a client can check a bundle without trusting eye: every item has `fact`, `value`, `sourceId`, `publisher`, `upstreamUrl`, `retrievedAt` (ending Z) and `link`; a null `value` carries a `note`; an item with no `upstreamRecordUrl` says "no record-level URL: why" in its note; an `upstreamRecordUrl` sits on its own publisher's host (`lib/mcp/worldHosts.ts`, the table the test reads too); `kind` is `"about-eye"` (a claim about eye's own catalogue, which has no publisher record, and nothing else may be called that) or `"estimate"` (a count eye computed from a route's list, not a number the publisher states); an `estimate` carries `inputs`, a non-empty list of `{ sourceId, route, upstreamRecordUrl?, retrievedAt }` (the source, the eye route whose reply held the rows, the publisher's own URL for the list or layer the route read, and that source's own retrieval time), and only an `estimate` has `inputs`; a topic with `missing` entries has a `coverageStatus`, a reply with `truncated` has one, and its `status` is `"partial"` and nothing else; `missing` entries and `basis` lines are the typed ones above. An `isError` reply carries the typed error envelope instead of the bundle, and the schema accepts it too, because the MCP SDK's client checks `structuredContent` against the schema even when `isError` is true.

The server checks every non-error `world_context` reply against the schema before sending it; a reply that fails comes out as an `isError` reply with code `internal_error` and the validator's message, never as a plain result. SDK 1.30's `registerTool` accepts only zod schemas for `outputSchema`, so the server adds the JSON Schema to `tools/list` itself and validates with the SDK's own JSON Schema validator (`lib/mcp/server.ts`); a test pins both. `fema-nri` and `hifld-hospitals` share one ArcGIS org, so the schema separates publishers, not those two layers.

## Versioning promise

Written 2026-10-20. Two numbers, and they are not the same thing:

- `SERVER_VERSION` (`lib/mcp/server.ts`) is the server string: `serverInfo.version` at `initialize`, `version` in `GET /api/mcp`, and `info.version` of `public/openapi.json`. It is `0.5.0` today (CHANGELOG.md: 0.5.0 added `kind` `"estimate"` and `inputs` to the `world/2` item, additively).
- `schemaVersion` (`"world/2"`, `WORLD_SCHEMA_VERSION` in `lib/mcp/worldSchema.ts`) is the shape of a `world_context` reply. A bump of `SERVER_VERSION` is not a bump of `world/N`; a `world/N` bump is Cam's call.

The promise, and which part a test enforces:

1. What `tools/list` says (tool names, titles, descriptions, input schemas, annotations, `_meta`) and `world_context`'s `outputSchema` change only together with `SERVER_VERSION`, and every version has a dated entry in `apps/map/CHANGELOG.md`. Enforced: `lib/mcp/server.test.ts` ("versioning promise") hashes the real `tools/list` reply and fails when it differs from the entry `lib/mcp/server.lock.json` holds for the current `SERVER_VERSION`, when `SERVER_VERSION` has no entry there, or when an entry has no dated CHANGELOG.md heading. The same test holds `public/openapi.json` to `SERVER_VERSION` and to the production origin (`PUBLIC_ORIGIN`). A change to a description's wording is a version bump too; a bump is cheap on purpose.
2. `world/N` is additive within N. A property, an enum value or a rule may be added. A property is not removed or retyped, a required field is not relaxed, and a const or an enum value is not dropped. Enforced: `lib/mcp/server.schema-compat.test.ts` compares the published schema with the baseline committed when N was first published (`lib/mcp/server.world-2.schema.json`, never edited).
3. A breaking change to the reply is `world/N+1`, served beside `world/N` for 90 days, both named in CHANGELOG.md. Promise only: nothing can test it until a `world/3` exists.
4. A tool, or an argument of a tool, that is removed or renamed is announced under "Deprecated" in CHANGELOG.md at least 30 days before it goes. Promise only: the lock sees the removal, not the notice.

What this does not cover: the other tools relay a route's JSON as it is and publish no schema, so a route's own fields can change without a `SERVER_VERSION` change (each route's provenance names its source and release); the compat test does not read patterns or length limits; and the lock is append-only by convention, not by a check, so a reviewer reads its diff.

## Estimates and their inputs

`Provenance.kind` (`lib/provenance/types.ts`) says how a value was made: `published` is relayed as-is, `estimate` is computed here from published values, `snapshot` is our own observation of a live feed. A value computed here is an estimate and names what it was computed from: an optional `inputs` list on the entry, each input with `sourceId`, `upstreamRecordUrl`, `retrievedAt` and, where the publisher states one, `releasedAt`, and `rowIdsAt`, the path in the reply where the row ids are. The field is additive: no property was removed or retyped. On `Provenance` it changed neither `tools/list` nor the `world/2` `outputSchema` (so W5A, #87, left `SERVER_VERSION` at `0.4.0`). A `world_context` item is not a `Provenance`: it states its own source, route and retrieval time, so its `inputs` are a property of the published item schema, which is why adding them moved `SERVER_VERSION` to `0.5.0` (a dated CHANGELOG.md entry and a new lock entry, under the Versioning promise above).

Served today: `place_export` (`GET /api/catalog?op=place-export`). Each export's county counts are one `estimate` entry whose `inputs` are the publisher's layer (its URL and fetch time, with `releasedAt` the service's last-edit time) and the TIGERweb county rows the export joins to. The row ids are in the reply: `data.siteIds` for `npl-status` (county to EPA site ids), `data.sourceIds` for the two UST exports (county to the UST Finder row's OBJECTID) and `data.propertyIds` for `fuds-properties`. The TIGERweb entry stays `published`: it is relayed as-is.

Also served, since W6A (0.5.0 for the first): the five count lines `world_context` builds, which the publisher states no number for. Reading `lib/mcp/world.ts` for every line written as `noRecord("a count ...")` finds four builders: Severe or Extreme NWS alerts touching the box, M4.5+ earthquakes touching the box, `hospitals found` / `dams found` (one builder, both sources) and the SEC bundle's `public companies ... 0`. The item still has no `upstreamRecordUrl` (nobody publishes a URL for this box) and its note still says so. For hospitals, dams and companies only the zero case is a count line (a non-empty list emits its record rows); the NWS and USGS counts are emitted for every box. Those two tools publish no schema, so their change is outside the lock; it is in the changelog entry all the same.

Enforced by `lib/provenance/estimates.test.ts` (run by map-ci): an entry labelled `published` whose method says it was computed here (the words computed, aggregate, sum, count, derived, per year, change), or that names `inputs`, is a finding, and so is an estimate with no inputs. The rule is shown to find a planted violation, a violation planted deep in a fixture's recorded route, and the mutations "label the county aggregate published" and "drop its inputs". Two walks use it, and they are not equal evidence. The place-export walk is live: it fetches each of the four place-export replies through the route, finds one labelled aggregate in each (an `estimate` that names two inputs) and nothing published and computed. The fixture walk is a forward guard, not a measurement: the twelve recorded `world_context` fixtures hold 519 provenance-shaped entries and 0 of them carry a `kind`, so that walk judges 0 labelled entries today and cannot fail until a fixture is re-recorded with labelled entries (the test pins the 0, so that day fails a line and someone looks). `lib/catalog/placeExport.test.ts` holds the inputs to the export file's own `meta`.

Also enforced by `lib/provenance/provenance-kinds.test.ts` (run by map-ci), which closes the gap the two walks above leave: it reads the source of `apps/map/lib` and `apps/map/app` and judges every object literal written with `kind: "published"` by its `method`, so a seventh computed-and-published entry fails a test whether or not a fixture or a route test reaches it. It fails an entry whose method says computed, aggregate, sum, count, per year, change or derived, one that names `inputs`, and one whose method is not a literal (its words cannot be read). One reviewed exception is listed in the test with its reason (BLS QCEW's own over-the-year change), and it fails if it stops matching. A planted entry, appended to a real file, turns it red. A lexer that knows comments, strings, templates and regex literals finds the entries, so a brace or a quote in text cannot hide one. It tells an entry from a type by what follows the string, reading past whitespace, line and block comments, `as const`, `as T` and `satisfies T`: a comma, a closing brace, one of those assertions or a doubled `||` or `&&` is an entry (so `kind: "published" as const,`, `kind: "published" satisfies Kind,` and a last property with a trailing comment, `kind: "published" // note` then `}`, are judged, and `kind: "published" || "estimate",` is an entry whose kind is an expression, which the test refuses); a lone `|` or `&`, a `;` or the next member of an interface is a type. W6A round 2 added that reading: until then the lexer looked at one character, filed those three forms as types, and never judged them (latent: none was `published`). W6A round 3 added `||` and `&&`: until then the lexer and the third check below both took the first `|` or `&` for a union or an intersection, so `kind: "published" || "estimate",` balanced as a type and was never judged (latent too: none was `published`; tsc accepts it and the type stays `"published"`; no lint rule was found to refuse it: eslint-config-next 16.3.4 and typescript-eslint, read in another checkout with eslint 9.39.5, do not enable no-constant-binary-expression, and this repo's pinned 16.4.2 and eslint 10 were not installed here to read). A second check fails if the entries plus type members it reads differ from the number of times `kind: "published"` is written as code. That count balances whatever the lexer decides, so a third check fails if any type member does not also read as a type in the raw text (a lone `|` or `&`, a `;` or the next member after it): a form the lexer cannot place, such as `kind: "published".toString()`, is refused and not filed.

What this does not cover, as of 2026-10-20:

- The words are a heuristic. A method that computes without saying so passes the word check; the `inputs` half of the rule and a reviewer cover that.
- The source walk sees `kind: "published"` (or `'published'`) written as a property of an object literal, followed by a comma, a closing brace, a comment, `as const`, `satisfies T` or (refused) `||` or `&&`. Not seen, checked by planted source on 2026-10-20: a published entry made by spreading another object (`...base`; the base object is judged, the override is not), a kind held in a variable, a quoted key (`"kind": "published"`), a value in parentheses or backticks (`kind: ("published")`, `` kind: `published` ``) and one chosen by a ternary. The raw-text check spells the property the same way, so it cannot see these either, and the count of entries is a floor. Fail-closed, not hidden: a `method` written `"..." as const` is read as not a literal and refused, and a type literal written with commas (`{ kind: "published", method: string }`) reads as an entry whose method is not a literal and is refused (write it with semicolons).
- Refused rather than judged, none of them in the tree on 2026-10-20 (each shown by planted source, and pinned by `provenance-kinds.test.ts`): `as const` or `satisfies T` on the line after the value (`kind: "published"`, then `as const,` on the next line) is read by the lexer as a clean entry, but the raw-text check reads the next line's first word as the next interface member, so the two readings disagree and the file is refused until the value and the assertion share a line. And `COMPUTED_METHOD`'s `changes?` and `counts?` flag a published method whose prose merely uses the word ("the station count the publisher lists", "the publisher changes this list each release"): a false positive that fails the walk, and the way out is the reviewed list in the test (BLS QCEW's own over-the-year change is such a case), not a pass.
- Neither refused nor judged: `kind: "published" | 0,`, `kind: "published" & 1,` and a newline then `in obj` after the value share the round-1 slip (the lexer files the first character as a union, an intersection or the next member, and the raw-text check reads it the same way), so each balances as a type and nothing judges it. The round-2 reviewer reports that tsc refuses all three; that was not run here and not planted in a test, and the map-ci `tsc` step is what would stop them. `kind: "published" as const || "estimate",` is read as an `as const` entry and judged by its method only; the `||` after the assertion is not read.
- Only `published` is judged. Entries labelled `estimate` elsewhere (finance, screener, the watch resolver, the catalogue search) are not required to name `inputs`; that is the next step of this rule and is not done.
- Derived text in a `world_context` item that is not a count line is not labelled: the list `NRI hazards rated Very High or Relatively High` (filtered here from the NRI row, which is its record), the `N of M PFAS` figure in a UCMR 5 status note, and `FEMA declarations listed` 0 (a publisher query that returned zero rows, with that query as its record URL). Each has a record URL a reader can open; none is a count the publisher lacks a URL for.

## Security notes

- Read-only. Every tool is a GET against this app's own routes; annotations say `readOnlyHint: true`, `destructiveHint: false`.
- Keyless. No credentials are read, stored or forwarded. Optional operator keys (`x-gev-*` headers in the browser) never pass through MCP.
- Rate limits are inherited from the API: the routes cache in memory, gate concurrency per upstream and back off on 429. The MCP layer adds no fetches of its own beyond the one route call per tool call, except `social_vulnerability` (two routes) and `world_context`, which calls up to twelve of this server's own routes in two phases, each phase capped at 25 s, and no upstream directly (see [JEV.md](JEV.md)) What that does and does not bound is under Publisher budget below.
- CORS is open (`*`) like the rest of `/api`; the endpoint validates `Content-Type` and body size, and the Origin header is not restricted because nothing here is session- or cookie-bound.
- Stateless per request: a new `McpServer` and transport are created for each POST and closed after the response, so one client cannot affect another.
- No people. The tools return aggregates (counties, ports, countries) and public SEC/FDIC/USAspending records about institutions; nothing here identifies a private individual, and the prompts repeat the project's ethics guardrails.

### Publisher budget (2026-10-20)

There is no cap of one request per second per host, and this document does not promise one. `world_context` calls no publisher itself: it calls this app's own routes, and those reach publishers through `cached()` and `polite()` in `lib/server`. Under 50 concurrent callers against a recorded fetch (`lib/server/upstream.load.test.ts`), callers asking for the same thing share one publisher call; a `polite()` gate starts calls no closer than the interval its call site gives it (40 ms to 2 s, read from the call sites, not machine-checked) and queues the rest; and once a publisher answers 429 the gate closes for its back-off (20 s to 10 min, per call site), so every caller queued behind that answer, and every later one until it ends, gets the same error at once and the publisher is not asked again. Where a route answers 502 through `jsonError`, a tool that relays it returns that error as `rate_limited` (`retryable: true`); a route that lists the source in `failed[]` (`/api/fabric`, `/api/live`) answers 200 and the tool relays that with its caveat; `world_context` lists the source as a missing entry with code `failed` and action `retry`; a caller still waiting past its route's deadline gets `timeout` (`world_context`: 25 s a phase). The gate is keyed by name and kept per server process, not per host or per deployment: in the same test five 100 ms gates on one host start 50 calls inside one second (the test asserts that number, so this sentence cannot drift from it), and each instance counts for itself. `world_context` reaches this through `/api/live`, which looks up the outline of each NWS zone its alerts name at 40 ms, up to 160 on a refresh. A flat one-second floor per host would slow that lookup 25-fold, so none was added; whether to cap a host, and for every caller or only MCP traffic, is open and waits on Cam. The test writes the one-call-per-second promise as an expected failure, so the day a cap lands that test fails and it and this paragraph change together. Calls the routes make straight to `upstream()`, with no gate, are held only by `cached()`: the NWS alerts and USGS earthquake feeds behind `/api/live` are two, kept 5 minutes when both answer and asked again by the next caller when one fails.

## Environment

| Variable | Used by | Meaning |
| --- | --- | --- |
| `GEV_BASE_URL` | stdio server, HTTP route (optional), `examples/gev.py` | Base URL of the HTTP API the tools call. The route defaults to its own origin; the stdio server and the Python client default to `http://localhost:3000`. |
| `VERCEL_AUTOMATION_BYPASS_SECRET` | HTTP route only | Set by Vercel once the project turns on "Protection Bypass for Automation", and then exposed to every environment, production included. The code is what keeps it in: the route's sub-requests send it as `x-vercel-protection-bypass` only when `VERCEL_ENV` is `preview`, the request's origin is the deployment's own `https://VERCEL_URL` or `https://VERCEL_BRANCH_URL` (a spoofed Host gets no header), and the sub-request goes to that same origin (never to a `GEV_BASE_URL` on another host). A sub-request that carries it never follows a redirect: a 3xx comes back as an error reply with its status, without the `Location`. Production, local and stdio send no header. The visitor's cookie or share token is never forwarded. |

## Adding a tool

Append a `defineTool({...})` entry to `TOOLS` in `lib/mcp/tools.ts` with a zod input schema and a handler that calls `relay(ctx, "/api/...")`. Add its URL case to `lib/mcp/tools.test.ts`, its name to the snapshot in `lib/mcp/server.test.ts`, and regenerate this table. The HTTP route, the stdio server and the GET manifest pick it up with no further wiring.
